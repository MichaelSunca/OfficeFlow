## ./mvnw clean package -DskipTests -U

这个命令是 Java 后端开发中最常用的指令之一，它代表了 Maven 构建生命周期的核心流程。作为资深开发，理解它背后的机制比记住命令本身更重要。

我们将这个命令拆解为四个部分来详细分析：

### 1. `./mvnw` (Maven Wrapper)

* **含义**：`mvnw` 是 **Maven Wrapper** 的缩写。
* **作用**：它是一个脚本（Windows 下是 `mvnw.cmd`，Linux/Mac 下是 `mvnw`）。它会自动检查你本地有没有安装 Maven。如果没有，它会自动下载并安装该项目指定版本的 Maven。
* **资深视角**：在团队协作中，这能保证所有人使用的 Maven 版本**完全一致**，避免因为“我电脑上的 Maven 版本太老”而导致的编译失败。

---

### 2. `clean` (清理阶段)

* **作用**：告诉 Maven 先把之前编译生成的 `target` 文件夹**全部删掉**。
* **为什么需要它**：Java 编译后的字节码文件（.class）存放在 `target` 目录中。有时候你修改了代码或者删除了类，但旧的编译文件还在。执行 `clean` 可以确保你这次构建是**从零开始**的，排除了旧文件的干扰。

---

### 3. `package` (打包阶段)

* **作用**：这是 Maven 生命周期的“重头戏”。它会依次执行以下动作：
1. **Validate**：验证项目结构是否正确。
2. **Compile**：将 `src/main/java` 下的 Java 代码编译成字节码。
3. **Test-Compile**：编译测试代码。
4. **Package**：将编译好的代码、资源文件（如 `application.yml`）以及依赖包，打包成一个可执行的 **`.jar`** 文件（存放在 `target` 目录下）。


* **结果**：执行完后，你会得到一个可以在服务器上运行的“成品”。

---

### 4. `-DskipTests` (跳过测试)

* **作用**：这是一个参数（Property）。它告诉 Maven：“虽然你要打包，但请**不要运行** `src/test/java` 下的单元测试用例”。
* **使用场景**：
* **开发中**：当你只是想快速看看代码能不能跑通时，跳过测试可以节省大量时间（尤其是当测试涉及数据库连接或网络请求时）。
* **构建失败时**：如果有些测试用例因为环境问题（如数据库没开）挂了，但不影响主程序逻辑，可以用它临时绕过。
* **注意**：在正式发布到生产环境前，**绝对不能**跳过测试，必须确保所有测试全绿。

### 5. `-U`
* **`-U`** 会强制 Maven 重新去网上找依赖，哪怕它之前记录过“下载失败”。
